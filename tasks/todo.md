### 方針
- 実績の区間所要時間から配達順を最適化する（LLM・外部API不使用）
- 理由: 今の構成（静的サイト + anon key）のまま実装可能・社外へのデータ送信なし・API費用なし
- 不採用案: アプリ内で Claude API 呼び出し（APIキー秘匿にサーバー関数が必要／認証なしで料金を不正に使われる恐れ／得意先名が社外へ出る／最短順の計算はLLMより普通のアルゴリズムが正確）
- 不採用案: 住所ジオコーディング（得意先住所が外部サービスへ出る）

### 前提データ
- `destinations` に緯度経度なし → 距離ではなく実績時間を使う
- `stop_records.departed_at` = その配達先へ向けて出発した時刻、`arrived_at` = 到着時刻
- 区間 = （同一 report 内の直前の到着先 or 会社）→ 当該配達先、所要時間 = `arrived_at - departed_at`
